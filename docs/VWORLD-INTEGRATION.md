# VWorld 국내 위치 검색

서버 `/etc/yeohaengit/server.env`의 `BOPok_VWORLD_KEY`를 사용합니다. Search API 2.0의 place/road/parcel 검색을 호출하며 EPSG:4326 x=경도, y=위도로 검증합니다. 주소처럼 보이는 입력은 도로명→지번→장소, 그 외는 장소→도로명→지번 순서로 조회합니다. 하나의 검색에서 최대 3회/총 6초, 요청당 2.5초로 제한합니다. 서버 프로세스당 하루 1,000요청 제한이 있습니다.

`BOPok_VWORLD_DOMAIN`이 있으면 인증 도메인 값으로 사용하고 없으면 기존 `BOPok_APP_URL`을 사용합니다. 발급 시 등록한 서비스 URL과 맞아야 합니다. 키는 서버에서만 전송되고 브라우저/Android/공유 링크에 포함하지 않습니다. 로그나 API 응답에 공급자 요청 URL/키/원문 오류를 출력하지 않습니다.

VWorld에서 여러 결과가 오면 사용자가 선택하도록 그대로 반환합니다. 좌표가 없거나 범위를 벗어나면 임의로 도시 중심 좌표를 넣지 않습니다. VWorld의 인증 오류/응답 지연/결과 없음은 기존 Nominatim 검색으로 이어지며 기존 요청 간격 제한도 유지합니다. 공급자별 캐시를 나눠 기존 검색 결과가 새 VWorld 검색을 가리지 않도록 했습니다.

기존 `/api/location`을 사용하는 웹과 Android에 모두 적용됩니다. 이 변경은 주변 교통시설 공급자나 지도 업체 영업 여부, 교통 시간표를 바꾸지 않습니다. 키 파일 편집 후 기존 컨테이너 재시작만으로는 새 환경변수가 반영되지 않으므로 재배포해야 합니다.

배포 ZIP을 푼 소스 폴더에서 실제 컨테이너 연결 검사:

```bash
sudo -n docker exec -i yeohaengit-web node --input-type=module < scripts/check-vworld.mjs
```

실제 서버 키는 개발 환경에 없으므로 권한/등록 도메인/실제 검색 응답은 위 검사로 확인해야 합니다. 모의 공급자 테스트는 좌표 순서, 주소 검색 순서, 캐시 분리, 키 비노출, 기존 검색 fallback을 검증합니다.
