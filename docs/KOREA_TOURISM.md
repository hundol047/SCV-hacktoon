# 국내 전국 수집 자료 (0.5.0)

기존 앱은 도시 중심 반경 1~50km에서 최대 200개 후보만 조회했습니다. 이번에는 전국 등록 자료를 별도로 보관하고, 전국 목록과 여행 한 건의 후보 제한을 분리했습니다. 현재 앱에서 제공하는 전국 자료는 OpenStreetMap입니다. 관광공사의 공식 전국 목록은 인증키가 없어 아직 수집하지 않았습니다.

## 실제 수집 범위

지역별 합계는 경계에 걸치는 객체를 중복 포함하므로 전국 고유 OSM ID 합계와 다를 수 있습니다.

`node`, `way`, `relation`에서 tourism 전체, historic 전체, 음식점·패스트푸드·푸드코트·카페·벤치·공연장·예술시설, 해변, 공원·자연보호구역·정원·워터파크·스포츠센터, 국립공원 경계, 쇼핑몰·백화점·선물/기념품점을 수집했습니다. **OSM에 등록되지 않은 실제 관광지, 모든 자연 지형·종교시설·소매점, 사진·상세 설명·축제/실시간 영업 정보를 전수 확보한 자료가 아닙니다.**

기존 17개 시·도에 해당하는 지역 구획을 수집 범위로 사용합니다. 수집 당시 OSM/Nominatim은 광주광역시·전라남도 경계를 `historic`으로 표시했습니다. 광주 조회에는 현재 지도상의 `전남광주통합특별시` 명칭이 함께 반환되었습니다. 이를 현재 행정구역의 공식 확정 자료로 간주하지 않고, 기존 경계와 공급자의 상태를 coverage와 화면에 그대로 표시합니다.

같은 OSM ID를 가진 항목은 합치고 여러 지역과 겹치면 모든 해당 구획을 보존합니다. **서로 다른 OSM 객체가 같은 실제 업장을 나타낼 수 있으므로 등록 항목 수는 물리 시설의 고유 개수와 다릅니다.** 이름 없는 벤치 등도 내려받는 전체 자료에는 포함합니다. 주소·좌표가 없으면 미등록으로 남깁니다. 선택한 tag만 보관하며 전체 OSM 객체/도형의 덤프는 아닙니다.

## 앱에서 사용

여행 준비에서 실제 모드 → **전국 수집 자료 열기**를 선택하세요. 전국 전체 또는 지역·분류·이름/주소/tag 검색이 가능하고, 페이지 이동으로 결과 전체를 볼 수 있습니다. 목록은 보관된 데이터에서 읽어 오므로 Supabase·관광공사 키·지도 공급자 연결 없이도 검색합니다.

일정에는 한 지역을 선택하고 시·군·구 검색어로 범위를 좁힐 수 있습니다. 이 검색은 **이름/주소/tag 문자열에 대한 검색**이며, 주소에 도시가 없는 항목까지 시·군·구 경계로 분류한 자료가 아닙니다. 일정 후보는 이름과 좌표가 있는 관광·문화·역사·공원·음식점·카페·쉼터 최대 200개를 사용합니다. 숙박·쇼핑·레저는 검색 목록에 남기고 자동 관광/휴식으로 바꾸지 않습니다. 도 전체를 선택하면 장소 간 거리가 클 수 있습니다. 후보 배정 시간은 실제 이동 시간이 아니며 경로를 따로 확인해야 합니다.

좌표는 노드 또는 OSM 객체의 중심이며 시설 입구를 보장하지 않습니다. wheelchair=yes, cuisine, opening_hours만으로 무계단·실제 메뉴·예산·영업을 확정하지 않습니다. 미확인 시설·보행·비용은 null을 유지합니다. 경로 조회는 인증된 서버/실제 공급자 설정이 별도로 필요하며, 전국 snapshot의 좌표도 조회에 사용할 수 있습니다.

- `GET /api/tourism`: q, province, category, page, limit(1~100), 전체/검색 건수·coverage·stale 표시.
- `GET /api/tourism?action=catalog&province=KR-11&q=경복궁&limit=200`: 선택 지역의 일정 후보, limit 10~200.
- `GET /api/tourism/download`: 전체 수집 JSON의 gzip 다운로드. 큰 응답을 스트리밍합니다. 실제 Vercel 계정에서의 다운로드는 아직 검사하지 않았습니다.

ODbL 출처/라이선스를 표시하고 전체 수집 자료를 다운로드할 수 있습니다. [라이선스](../data/korea-tourism/LICENSE.md)를 함께 유지하세요.

## 다시 수집

Node 24에서 실행합니다. 평소 앱 설치/빌드는 Git에 포함된 snapshot을 사용하며 외부 사이트를 다시 수집하지 않습니다.

```sh
npm run data:korea
```

HTTPS proxy가 있는 클라우드에서는 `NODE_USE_ENV_PROXY=1 npm run data:korea`로 실행했습니다. `-- --fresh`는 24시간 이내 자료 캐시도 갱신합니다. 지역 경계 캐시는 7일 이내만 재사용합니다. 기본 수집은 결과 개수 제한 없이 서버 자원 예약을 25초/128MiB로 낮춘 순차 요청이고, 실패한 큰 질의는 분류별 작은 질의로 나눕니다. 429의 Retry-After/대기와 504 재시도에 상한을 둡니다. 실패한 분류·지역 뒤에도 독립 지역을 계속 수집합니다.

.cache/korea-tourism/collector.lock으로 중복 실행을 막습니다. 정상 종료·SIGINT/SIGTERM에서 lock을 제거합니다. 강제 종료 후 남으면 실행 중 수집기가 없는지 확인한 뒤 그 lock 파일만 제거하세요.

지역/분류 캐시는 `.cache/korea-tourism`에 저장하고 Git에 넣지 않습니다. **잘린 응답, 공급자 runtime remark, 중복 ID, 17개 구획 누락·건수 불일치가 있으면 공개 snapshot을 교체하지 않습니다.** 다음 실행은 검증된 캐시에서 재개합니다. 캐시가 있는 분류의 이전 수집 시각을 유지합니다. 공급자 가용성에 따라 수집이 오래 걸리거나 재실행이 필요합니다.

완료 후 `npm test && npm run build`로 데이터/앱을 검증하고 서버를 재시작·재배포합니다. 실행 중 서버는 snapshot을 메모리에 보관하므로 파일 수집만으로 기존 프로세스의 자료가 바뀌지 않습니다. 빌드의 standalone 추적에 snapshot/manifest가 포함됩니다.

## 공식 관광공사 기본 목록

`npm run data:korea:official`은 KorService2 `areaBasedList2`의 전국 기본 목록을 100개씩 마지막 페이지까지 받는 별도 수집기입니다. 환경 설정에 발급받은 **원문(Decoding) BOPok_TOURAPI_KEY**가 필요합니다. URLSearchParams가 전송 시 인코딩하므로 인코딩 키를 다시 넣지 않습니다. 키를 채팅/Git에 넣거나 NEXT_PUBLIC로 노출하지 마세요.

최대 2,000회 요청으로 제한하고 페이지/전체 건수·중복 ID·응답 상태를 확인합니다. 전체 건수가 수집 도중 바뀌거나 인증/쿼터가 실패하면 기존 공식 파일을 보존합니다. 오류 로그에 키/요청 URL/공급자 메시지를 출력하지 않습니다. `tourapi-basic.json.gz`와 별도 manifest로 저장하며 사진과 상세/intro/repeat API를 수집하지 않습니다. **현재 이 공식 파일은 없으며 앱 목록은 OSM만 제공합니다.** 공식 자료 수집 후에는 이용 조건과 교차 출처 중복/분류를 확인해 별도로 통합해야 합니다.

## 검증

최종 TypeScript·프로덕션 빌드와 **단위 144개(16개 파일)**를 통과했습니다. 전체 브라우저 **120개** 통과 후 같은 지역의 다른 검색이 별도 도시로 취급되지 않게 수정하고, 관련 실제 전국 자료 **8개**를 네 구성에서 다시 통과했습니다. 최종 Docker의 키/DB 없는 검색·서울특별시 후보·전체 gzip chunked 다운로드/SHA/UID1000을 확인했습니다. DB/키 없는 컨테이너에서 실제 Chromium으로 전국 검색→경복궁 후보 28개→실제 모드 일정 생성도 통과했습니다. [검증 기록](VALIDATION.md)에 기존 검사와 외부 미검증 범위를 구분했습니다.

실제 TourAPI 인증·페이지 응답 성공은 미검증입니다. 그 수집기의 마지막 페이지 방문·건수 변경/키 누락/인증 실패 시 기존 파일 유지·키와 사진 비노출은 격리된 모의 응답으로 검사합니다. 실제 관광 시설의 현장 검증을 이 데이터 수집 결과로 대신하지 않습니다.
