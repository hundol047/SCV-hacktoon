# 헤더 로그인과 AI 코스 생성 점검 개선

로그인을 헤더의 작은 버튼으로 이동했습니다. 클릭하면 입력창이 펼쳐지며,
모바일에서도 팝업이 화면 밖으로 벗어나지 않도록 제한합니다.

짧은 연결 확인은 일정 생성 성공을 보장하지 않았습니다. 기존 코드는 별도의
outputConfig JSON 스키마 기능을 요구했고, reasoningContent와 최종 text가 함께
오면 유효한 텍스트도 거부했습니다. 이제 기본 Converse 필드만 사용해 JSON을
요청하고 최종 텍스트를 파싱합니다. Zod 검증, 후보 ID/중복 검증, 비용 예약은
유지합니다. reasoningContent는 응답이나 로그에 노출하지 않습니다.

코스 응답 토큰 상한은 기존 예산 예약 범위인 1600, 응답 제한시간은 60초입니다.
요청 형식 거절·권한·시간 초과·응답 잘림·유효하지 않은 추천·후보 부족을 구분해
안내하고 오류 코드만 서버에 기록합니다. 기존 일정은 실패 시 덮어쓰지 않습니다.
다일 일정 실패는 실패한 날짜를 함께 표시합니다.

배포 사전 검사는 동일한 JSON 생성 코드로 두 후보 ID 추천을 요청하고 응답과
후보를 검증합니다. 실패하면 기존 컨테이너를 중단하지 않습니다.
강릉 3일치 실제 로컬 관광지 자료의 후보 선정과 응답 파싱은 격리 테스트로
확인했습니다. 사용자가 올린 기존 오류의 정확한 원인은 당시 서버 로그가 없어
확정하지 못했습니다. 실제 EC2 모델의 개선된 JSON 생성 검사는 새 배포 시 수행됩니다.
