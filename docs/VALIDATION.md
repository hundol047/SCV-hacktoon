2026-10-08, Bopok 0.3.0, Node 24.19.0, npm 11.9.0. 앱 검사는 Linux 프로덕션 standalone 빌드를 사용했습니다. 외부 운영 계정은 사용하지 않았습니다.

| 검사 | 결과와 범위 |
| --- | --- |
| TypeScript + 프로덕션 빌드 | 통과. 계정·검토·운영·다도시 화면/API 포함 |
| `npm test` | 11개 파일, **111개 통과** |
| Playwright | **88개 통과**: 데스크톱 Chromium·모바일 Chromium·Firefox·WebKit 각 22개 |

| 계정·가족·독립 검토 | 격리된 Auth 응답/SQL로 이메일 코드, 익명 여행 이전·계정 복원·권한·충돌·링크 폐기·다른 검토자 승인·서명 유지 확인 |

| 최신 Docker runtime | 비루트 실행, 홈 200·규칙 추출·liveness 200, 미구성 readiness 503 확인 |

단위/SQL 검사는 이전 시연·고정 일정·공유 권한·복구·한도에 더해 구형 마이그레이션의 준비 판정 거부, 미구성 503, OTP/토큰 갱신·역할 검증·봇 검증, 시설 서명 변조·자기 승인 거부, 도시별 후보·DST·현지 날짜·통화/환율·도시 간 이동·비용 누락, 개인정보 없는 지표·알림 중복 억제·운영 인증을 확인합니다.

브라우저 검사는 작성·수정·비교·부모님 의견·복원·삭제·인쇄 흐름과 계정 이전, 서버 연결 유지·동시 변경, 실제 도시 UI의 정보 부족 표시, 출처 기록의 제출→다른 검토자 승인→저장/새로고침을 검사합니다. SQL은 격리된 PGlite이며 Auth·경로·AI·도시 응답은 모의 공급자입니다. 실제 이메일 발송이나 유료 API 성공을 뜻하지 않습니다. Chromium에서는 PDF 파일도 생성했고 다른 엔진에서는 인쇄 CSS/이벤트를 확인했습니다.

실제 PostgreSQL 검사는 직접 생성한 임시 Docker DB에서 실행했습니다. pg_cron 예약 주기는 검증 시 1초로 줄여 실행을 확인했고, 운영 마이그레이션은 매시간입니다. public 스키마만 백업하며 운영 Supabase Auth 계정까지 복원한 검사는 아닙니다. 실제 알림은 보내지 않고 모의 endpoint의 재시도·중복 억제를 검사했습니다.

## 외부 연결의 관측 결과

실제 Nominatim 서울·파리·뉴욕 검색은 HTTP 200·좌표/국가 응답 검증에 성공했습니다. 이전 0.2 검증의 서울 Overpass는 HTTP 200·원본 500개에서 30개 후보 생성에 성공했으나, 이번 대표 도시 호출에서는 HTTP 504가 발생했습니다. 공급자 가용성을 보장하지 않습니다. 환율 호스트는 현재 적용된 클라우드 허용 목록에서 CONNECT 403으로 차단되어 있으며 필요한 도메인을 설정 초안에 추가합니다. 초안이 적용되기 전 실제 환율 연결 성공으로 표시하지 않습니다.

OpenAI·openrouteservice·Google Routes는 키가 없어 실호출 미검증입니다. 외부 Vercel·Supabase 운영 연결, 실제 메일/Turnstile·알림 수신·운영 DB 백업, 전 세계 시설 기록의 독립 검토는 운영 계정과 담당자가 필요합니다. 실제 iOS/Android·VoiceOver/TalkBack·물리 프린터와 새 클라우드 복원은 미검증입니다. 실제 기기 스크립트는 자격 증명 없으면 명확히 실패하며 모의 실행을 실기기 결과로 표시하지 않습니다.

클라우드 브라우저 라이브러리는 `/workspace/browser-deps/runtime`에 서명/체크섬을 확인한 Debian 패키지를 추출했습니다. Playwright 브라우저는 `/workspace/.cache/ms-playwright`입니다. WebKit 실제 실행을 확인한 뒤 이 환경의 호스트 자동 탐지 제약만 우회했습니다. CI는 `playwright install --with-deps`를 사용합니다. Firefox는 이 샌드박스의 프로필 접근 제약 때문에 승인된 별도 실행 권한으로 검사했습니다. TLS 검증은 유지했습니다.

전체 소스 Docker 이미지는 이전 0.2에서 빌드했고, 이번 0.3에서는 최신 standalone runtime 이미지를 새로 빌드·검증했습니다. 자세한 배포 조건은 [배포 절차](DEPLOYMENT.md), 1~7번 완료 범위는 [출시 준비 기록](RELEASE_READINESS.md)을 확인하세요.
