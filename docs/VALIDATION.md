브라우저 검사는 기존 시연/작성/편집/조건/복원/삭제/인쇄 흐름에 더해 두 독립 브라우저의 서버 저장·부모님 의견 동기화·읽기 권한·링크 폐기, 실제 자료 모드의 도시 검색 UI·정보 부족 표시·JSON 내보내기/가져오기를 검사합니다. 추가 점검에서는 화면 이동·새로고침의 서버 연결 유지, 로컬/원격 충돌, 쿠키 삭제 후 복구, 링크 폐기 후 표시 제거, 최신 의견 30개, 고정 ID 충돌, 실제 초안의 부모님 요청·음식 선호, 오래된 경로 갱신·고정 시간 보존, 사용자 시설 기록, 전체 저장·캐시 상한도 확인합니다. 서버 DB는 격리된 PGlite이며 실제 Supabase 운영 계정을 사용하지 않습니다. 도시 UI 테스트는 명시적인 모의 공급자 응답을 사용하며 위 실제 HTTP 응답 검증과 구분합니다.

AI 단위 검사는 구조화 출력, 잘못된 JSON/후보 ID/점검 코드, 원문에 없는 수치, 시간 초과/오류, 설명의 기존 규칙 근거 사용을 확인합니다. 실제 OpenAI와 openrouteservice 호출은 키가 없어 미검증입니다. 전달 IP를 인증 수단으로 사용하지 않으며 SQL 요청 제한을 끄지 않습니다.

실제 Supabase/pg_cron 작업·운영 DB 재해 복구·외부 Vercel 배포·새 클라우드 복원·실제 iOS/Android·스크린리더·물리 프린터는 미검증입니다. 모바일 검사는 Chromium의 화면/터치 에뮬레이션입니다. 초기 MVP의 PDF 생성/텍스트 추출은 이전에 성공했으며 최신 변경의 브라우저 인쇄 흐름은 이번 테스트로 확인합니다.

초기 Docker 소스 설치는 프록시 호스트의 DNS 해석 실패(EAI_AGAIN)로 막혔습니다. 기존 프록시 주소를 BuildKit 호스트 매핑에 추가하고 신뢰 CA를 secret mount로 전달한 뒤 설치·빌드를 완료했습니다. TLS 검증을 해제하지 않았으며 프록시 CA는 최종 이미지에 복사하지 않았습니다.
