# 동행자 중심 강원 여행: 구현과 현장 검증

## 구현한 흐름
- 일정 조건과 검증 결과를 접힌 패널로 제공. 기존 도로·운영·출발·귀가 재계산 API를 연결하고 변경 전후를 확인한 뒤 적용한다.
- 장소별 필수 시설의 등록 상태, 출처와 확인 날짜 표시. 출처 정보와 현장 인증은 구분한다.
- 하차/입구/관람/화장실/휴식/숙소 구간별 이용 경험과 운영자 문의 기록을 여행 문서에 저장한다. 사용자 기록으로 검증된 시설 데이터를 자동 변경하지 않는다.
- 숙소별 입구, 객실 진입, 이동 공간, 욕실 문의 양식을 제공한다. 예약할 객실의 확인 내용은 여행에 저장한다. 숙소 후보에 관광공사 무장애 상세 자료를 추가 조회하고 요청 시설과 최근 근거가 모두 일치하는 후보로 좁힐 수 있다. 누락·오래된 자료는 일치로 처리하지 않으며 객실 인증으로 표시하지 않는다.
- 지역별 증빙 수량, 결제액, 여행기간을 점검하고 기간 밖 영수증은 정산 합계에서 제외한다. 지정 관광지 적합성 및 심사 결과를 자동 판정하지 않는다.
- 신청 초안, 원본 사진, 파일 목록과 제출 전 확인 문서를 ZIP으로 내보낸다. 공식 서식이 아니며 미확인 원본도 포함하므로 사용자가 제출 전 검토한다. ZIP은 암호화하지 않는다.
- 원본과 수정한 초안을 AES-256-GCM으로 백업. PBKDF2-SHA256 310,000회, 임의 salt/IV. 암호는 서버로 전송하지 않는다. 복원은 원래 여행·지역으로 제한하고 증빙 확인 동의를 초기화한다.
- 복원은 IndexedDB 한 트랜잭션으로 수행한다. 다른 여행 자료 덮어쓰기와 전체 보관 한도 초과를 거절한다.
- 로그인 계정별 비공개 최신 백업 1개를 저장·복원·삭제하는 API. 소유자 식별은 서명된 로그인 세션에서만 얻는다. 파일 24MB, 요청 분당 6회/하루 60회 제한.

## 운영 적용에 필요한 설정
1. 기존 Supabase에 `supabase/migrations/015_private_evidence_backup.sql` 실행. 버킷은 비공개이며 anon/authenticated 읽기 정책을 추가하지 않는다. 기존 포괄 정책이 있다면 이 버킷을 제외해야 한다.
2. 기존 `BOPok_SUPABASE_URL`, `BOPok_SUPABASE_KEY`, 로그인 세션 설정을 유지한다. 서비스 키를 브라우저에 노출하지 않는다.
3. HTTPS로 서비스해야 브라우저 암호화와 로그인 보안을 사용할 수 있다. HTTP IP 접속은 암호화 백업 지원 대상이 아니다.
4. 실제 계정 두 개로 소유자 분리, 다른 기기 복원, 삭제와 암호 오류를 확인한다. 이 작업 공간에는 운영 자격증명이 없어 실제 클라우드 저장 검증은 수행하지 않았다.

## 실제 이용자 검증 계획 (아직 시행하지 않음)
- 강원 1~2개 지역의 짧은 코스를 선정하고, 시설 운영자에게 배정 가능한 객실·진입 동선을 확인한다.
- 부모님 동반 가족 및 이동 보조기구 이용자를 모집한다. 참여 여부와 기록 공유에 사전 동의를 받는다.
- 사전에 동행자의 보행 한도, 휴식 간격, 필수 시설을 입력한다. 이용 어려움이 예상되는 구간은 체험 대상으로 강행하지 않는다.
- 실제 구간 이동 시간, 예상과의 차이, 도움 필요 지점, 휴식 장소, 일정 변경 횟수를 기록한다.
- 여행 후 걷는 부담·휴식 충분함·안내 정확도(1~5점)와 개선 의견을 앱에 저장하고 여행 JSON을 내보낸다.
- 최소 5개 동행 그룹의 결과를 검토하고 반복되는 접근 장애 구간을 제외·수정한 뒤 재시험한다. 평균 점수뿐 아니라 이용 불가 사례를 별도 집계한다.

## 남은 외부 작업
실제 현장 측정, 운영자 답변, 사용자 체험 결과, 지역별 최신 공식 신청서와 확정 제출기한은 아직 확보하지 않았다. 해당 정보 없이 '검증된 무장애 코스', '자동 신청 완료'라고 표시하지 않는다. 계정 백업은 운영 저장소 마이그레이션·HTTPS 적용과 실계정 검증 후 사용한다.
