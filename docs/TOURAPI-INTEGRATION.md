# 국문 관광정보 연결

서버 `/etc/yeohaengit/server.env`에 `BOPok_TOURAPI_KEY`로 공공데이터포털 Decoding 키를 저장하고 서버 컨테이너를 재배포합니다. Docker는 시작 시 env-file을 읽으므로 기존 컨테이너를 단순 재시작하는 것만으로 새 키가 반영되지는 않습니다. 키는 웹·Android·ZIP에 넣지 않습니다.

일정 생성 후 `/api/place-details`가 선택된 기존 관광지 최대 20곳을 조회합니다. 국문 `KorService2/searchKeyword2`에서 정규화한 이름이 같고 좌표가 500m 이내인 유일한 후보를 찾은 다음 `detailIntro2`로 주소·전화·운영시간·휴무 정보를 보완합니다. 후보가 여럿이거나 이름/좌표가 맞지 않으면 적용하지 않습니다. 기본 관광지 후보 검색 자체는 기존 OSM 자료를 사용합니다. 따라서 49,677건 전체가 앱 검색 목록으로 교체된 것은 아닙니다.

조회는 동시 4개, 전체 7초, 요청당 최대 2.5초, 서버 프로세스당 하루 1,000회로 제한합니다. 결과는 최대 500곳/6시간 캐시하며 동시에 들어온 같은 장소 요청은 합칩니다. 키가 없거나 공급자가 실패하면 기존 정보를 유지합니다. 공식 데이터의 운영시간은 방문 당일 영업 여부 보장이 아닙니다.

사진·입장료·버스 시간표·영문 API는 이번 변경 범위 밖입니다. 기존 전국 기본 목록 수집 명령 `npm run data:korea:official`은 별도로 유지됩니다.

검증: 공급자 모의 응답으로 정확한 장소 매칭, 중복 후보 거부, 캐시/동시 요청 병합, 인증키 URL 인코딩, HTML 제거, 공급자 오류/키 누락 시 fallback을 테스트했습니다. 사용자 서버에서는 areaBasedList2 연결 성공 및 전체 49,677건이 확인되었지만 searchKeyword2/detailIntro2의 실제 호출은 배포 후 확인이 필요합니다.
