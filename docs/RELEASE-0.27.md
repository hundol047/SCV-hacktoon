# 여행잇: 실제 도로 기반 일정·예산·동행자·숙소

## 적용된 기능
- AI가 후보를 고른 뒤 서버에서 선택 장소 간 도로 시간표를 조회합니다. 자동차 경로를 조회하지 못하면 임의 20분 경로로 확정하지 않고 기존 일정을 유지합니다. OSRM 도로 기준이며 실시간 정체·공사·택시 실요금은 아닙니다.
- 첫 여행지에서 시작 / 출발지에서 출발을 구분합니다. 차량 출발 이동과 마지막 날 귀가 완료 시간을 일정에 반영합니다. 항공·배편 구간은 자동 차량 연결을 하지 않습니다.
- 박물관, 공원, 식당 등 장소 유형별 계획 체류 시간을 적용하고, 남는 시간을 강제로 긴 방문으로 채우지 않습니다. 명확한 운영시간을 해석할 수 있는 장소는 운영시간·휴무와 충돌하는 방문을 제외합니다. 복잡한 계절·예약·요일별 시간은 영업 중으로 단정하지 않습니다.
- 전체 인원 예산 입력과 할인 전후 예상 비용 비교를 추가했습니다. 조건 충족 인원을 직접 선택하며, 계산 가능한 등록 할인만 반영합니다. 입장료가 없는 장소는 사용자 입력 단가를 이용한 예상 절약액입니다. 최종 예약 견적이 아닙니다.
- 완료 장소를 체크하고 남은 일정만 재추천할 수 있습니다. 비·눈·폭염은 실내 확인 자료가 있는 장소를 대상으로 하며, 자동 예보 조회도 가능합니다. 완료 장소가 없으면 첫 여행지를 기준으로 시작합니다. 변경안 확인 후 적용하며 귀가 시간도 재확인합니다.
- 공유 링크 동행자 투표·의견 저장, 새로고침 및 30초 간격 조회를 추가했습니다. 변경 투표가 많은 장소를 재추천에서 제외합니다. 자유 서술 댓글은 여행자가 확인하는 의견이며 자동 명령으로 실행하지 않습니다.
- 마지막 장소 주변 관광공사 등록 숙소를 조회하고 다음 날 첫 장소와의 거리를 함께 고려해 정렬합니다. 밤별 날짜·인원·객실 수를 예약 검색 링크에 반영합니다. 제휴 가격 API가 없으므로 객실 재고·실시간 가격·최저가를 보장하지 않습니다.

## 배포 시 꼭 필요한 DB 작업
동행자 투표를 사용하려면 Supabase 프로젝트의 SQL Editor에서 `supabase/migrations/013_group_votes.sql` 파일 내용을 한 번 실행하세요. 기존 여행·계정 데이터를 삭제하지 않습니다. 서버 service_role만 RPC를 호출할 수 있으며 공유 토큰은 해시로 저장됩니다. 초대 링크 유효기간은 30일입니다. 한 브라우저당 장소별 의견을 갱신하며 사람의 실명을 인증하는 투표는 아닙니다.

배포 ZIP에도 `013_group_votes.sql`을 넣었습니다. 이 SQL을 적용하지 않아도 일반 일정 생성은 사용 가능하지만 동행자 투표는 서버 설정 오류 안내를 표시합니다.

## 필요한 기존 설정
- 관광정보 키: `BOPok_TOURAPI_KEY` (운영시간·숙소 조회)
- 기존 Supabase 서비스 연결과 세션 설정 (투표·조회 제한)
- 서버에서 OSRM, OpenStreetMap, 공공데이터포털, Open-Meteo HTTPS 연결
- 휴대폰 현재 위치는 별도로 HTTPS 배포가 필요합니다.

코드와 DB를 로컬 테스트 환경에서 검증하며, EC2 실서버에 직접 배포하거나 공급자 실시간 가격을 검증한 것은 아닙니다.

## 검증
- 단위 테스트 270개 통과: 출발·귀가 시간, 도로 조회 실패, 영업시간 파싱, 완료 일정 보존, 투표 저장/갱신, 할인 조건, 공유 호환성 포함.
- PC·모바일 Playwright 테스트 10개 통과: 일정 생성 입력, 별도 브라우저 초대 투표, 할인 비용 비교, 숙박 날짜·인원 검색 링크, 기존 공유 기능.
- TypeScript 및 Next.js 프로덕션 빌드 통과.
