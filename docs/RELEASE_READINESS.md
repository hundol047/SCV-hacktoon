# 최신 감사의 7개 항목 처리 결과

2026-10-08 · Bopok 0.4.0. 재감사에서 발견한 코드·자동화 문제를 수정하고 아래 검사를 실행했습니다. **공개 운영 서비스는 아직 개통하지 못했습니다.** 실제 운영 자격 증명·현장 기록·물리 기기가 필요한 부분은 완료로 표시하지 않습니다.

| 항목 | 이번에 해결한 내용 | 실제 운영에 남은 조건 |
| --- | --- | --- |
| 1. 반복 도시 이동·이동일 | 실제 날짜/도착 일차로 이동 선택. 모호한 기록은 미확인. 재방문·현지 시작일·날짜 변경선과 이동만 하는 날 지원. 관광/식사 빈 경고와 자동 생성 제외, 부모님 화면에 이동 시각·출처 표시 | 실제 운행·예약·이동 중 식사/휴식 확인 |
| 2. 키만으로 준비 판정 | 스키마 12, Google 대중교통 포함. 설정별 실제 성공 기록이 24시간 이내여야 통과. 키/모델 변경·연결 실패·기간 경과 시 503. 유료 검사는 AI 예산 예약과 명시적 선택 후 실행 | 실제 Supabase/Auth·Turnstile·OpenAI·ORS·Google 설정과 첫 연결 검사 |
| 3. 운영 배포 복구 | 후보를 도메인 연결 전에 검사. 전환 후 운영 주소·커밋을 재검사하고 실패하면 이전 배포로 복구·재검사. 초기 배포/복구 실패도 명시 | 실제 Vercel 계정·프로젝트와 공개 origin. 첫 배포에는 이전 버전 없음 |
| 4. 장애·지연·앱 다운 감시 | 실제 공급자/DB 실패·소요 시간 기록. 최근 15분의 오류율/지연 경고. 앱 밖에서 5분 주기 감시, 앱 다운 시 직접 알림, 실행 간 중복 억제 저장 | GitHub 기본 브랜치의 작업 활성화, 알림 수신처·비밀과 실제 수신 확인 |
| 5. 계정 누락 백업 | public·auth와 역할·계정/여행 개수를 함께 암호화. 격리 DB에서 계정 ID·비밀번호 해시·여행·RLS 복원 확인. 기존 객체·변조·잘못된 키 거부 | 운영 DB 첫 복원, 관리형 Supabase Auth 서비스/확장/프로젝트/Storage의 별도 복구 정책 |
| 6. 운영 연결·시설 근거 | 공급자 검사 버튼/CLI·일일 검사와 준비 게이트. 기존 독립 검토·서명 유지. 실환율 HTTP 200 확인 | Overpass 이번 조회 HTTP 504. 실제 원출처 확인과 다른 검토자 승인. 공개 배포·메일/봇·유료 연결 미검증 |
| 7. 기기·공유 부하 | 동시 사용자 20명의 저장·수정·공유·의견·권한·충돌·폐기·삭제 240요청 검사. 4개 브라우저·axe와 실제 기기용 부모님/의견 흐름, 수동 점검표 제공 | 실 iPhone/Android·VoiceOver/TalkBack·물리 프린터 및 운영 인프라 부하 측정 |

## 실행한 검증

- 타입 검사와 프로덕션 빌드 통과. 단위/SQL **121개**, 브라우저 **92개** 통과.
- 실제 PostgreSQL 17 + pg_cron에서 스키마 **12**, 예약 정리 실행, **합성 Auth 계정과 여행의 암호화 백업/복원**을 확인했습니다. 별도 새 PostgreSQL 서버의 누락된 역할도 재생성했습니다. 운영 Supabase Auth 서버를 복원한 결과는 아닙니다.
- 격리 DB/앱에서 동시 사용자 **20명·240요청**, p95 **222ms**, 검사 여행 삭제 확인. 유료 호출 0회입니다.
- 최신 비루트 Docker runtime에서 홈/규칙/liveness 성공과 미구성 readiness 503 확인.
- 운영 도메인 전환 실패 시 복구, 연결 실패/키 변경·기록 만료, 앱 다운 외부 알림·중복 억제는 모의 endpoint로 검증했습니다. 실제 배포/알림 수신 성공으로 해석하지 않습니다.

## 현재 외부 조건

Vercel·Supabase·유료 경로/AI·BrowserStack 자격 증명이 제공되지 않았습니다. 계정 없이 가능한 Vercel CLI 임시 배포도 시도했으나 “Temporary deployments aren't available for this attempt”와 로그인 필요 오류로 종료했습니다. 공개 URL이 생성되지 않았습니다.

Frankfurter 실환율 연결은 성공했지만 Overpass는 이번 검사에서 504였습니다. 세계 도시 검색이 세계 전체 장소의 완전한 데이터·시설 검증을 뜻하지 않습니다. 출처가 없거나 오래된 사실은 미확인입니다.

운영 연결 순서는 [배포 절차](DEPLOYMENT.md), 실제 수행 범위는 [검증 기록](VALIDATION.md), 실기기 절차는 [접근성 점검표](ACCESSIBILITY.md)에 있습니다. 클라우드 설정은 초안으로 저장하며 환경 설정에서 검토·저장·게시해야 적용됩니다. 기능 브랜치 푸시만으로 기본 브랜치의 예약 작업이나 운영 서비스가 활성화되지 않습니다.
