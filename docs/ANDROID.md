# 보폭 안드로이드 개인 AI 연결 미리보기

앱 ID `kr.bopok.offline`, 버전 `0.8.0-weather-course`(versionCode 6), Android 8.0(API 26) 이상. 최신 Android System WebView를 사용하세요. 개인 AI 요청을 위한 인터넷 권한을 사용합니다. 위치·연락처·공용 저장소 권한을 요구하지 않으며 사용자가 선택한 문서에만 파일을 저장합니다. 이전 APK와 같은 로컬 서명키로 빌드해 업데이트 설치를 지원합니다.

## 0.8.0 날씨·유사 관광지·날짜별 코스
- 출발 기준 장소와의 직선거리를 후보 선정 단계부터 사용하고 AI에도 전달합니다. 출발 기준에서 첫 관광지까지의 이동은 코스 거리와 별도로 확인해야 합니다.
- coursePlans에 날짜별 코스를 저장하고 모든 선택 날짜를 함께 생성합니다. 다른 날짜에 선택한 관광지는 중복 추천에서 제외하며, 날짜별 삭제·JSON 보관을 지원합니다. 기존 taxiPlan은 호환용 현재 선택 계획입니다.
- 식당 자료가 있으면 조건과 날씨를 비교해 식사를 추가합니다. 없으면 이유를 표시하고 임의 장소를 만들지 않습니다. 관광 후 휴식을 배정하고 체류 시간을 30~120분 중 선택합니다. 휴식 장소의 좌석이 미확인이면 충족으로 판단하지 않습니다.
- 날씨는 여행일별 사용자 가정입니다. 실시간 예보가 아니며 기상청 확인 링크를 제공합니다. 맑음은 야외 기록 우선, 비·눈·폭염·한파는 야외 제외 및 실내 기록 우선, 특보는 자동 추천 중단입니다. 실내외 미확인은 확인 필요로 표시합니다.
- OSM의 indoor/outdoor 및 공원·해변·전망대 태그를 출처·수집 시각과 함께 보관합니다. 박물관·식당이라는 분류만으로 실내를 단정하지 않습니다. 기존 내장 자료에 indoor/outdoor가 없으면 미확인으로 유지하며, 새 수집 때 해당 태그를 보존합니다.
- 유사 관광지는 공통 테마·실내외 기록·보행 시간으로 비교하며 근거를 표시합니다. 키 없는 기본 유사 추천과 AI 추천 모두 날씨 조건을 반영합니다. 교체하면 해당 날짜의 계획만 해제합니다.

검증: 단위 테스트 167개, 타입 검사를 포함한 웹 빌드, APK 빌드·서명 및 APK 웹 자산의 모바일 저장/복원·모의 AI 흐름 통과. 실제 AI·도로 경로 키는 환경에 없고 Android 실기기 실행은 미검증입니다. 실제 요금·도로 시간·영업·주차 정보는 이번 업데이트로 확인된 것이 아닙니다.

화면 검증: 데스크톱/모바일 총 64개 중 첫 실행 63개 통과. 공유 링크 폐기 테스트가 Next.js 화면 전환 안내를 잘못 잡던 선택자를 실제 권한 거부 메시지로 한정한 뒤 관련 공유 테스트 6개 모두 통과했습니다. 새 날씨·출발지·날짜별 코스·식사/휴식·저장 복원 테스트는 양쪽 화면에서 통과했습니다. Android 실기기 확인 도구는 환경의 읽기 전용 홈 디렉터리 문제로 실행되지 않아 기기 검증을 주장하지 않습니다.

## 0.7.0 지역 맞춤 코스 추천

홈과 준비 흐름을 지역 → 취향·이동 수단 → 코스 추천 → 확인·적용으로 변경했습니다. 부모님 동행 조건과 큰 글씨 화면은 유지합니다. 국내 자료의 실제 분류인 자연 풍경·문화·전시를 선택할 수 있습니다.

기본 추천은 키 없이 등록된 자료의 조건·취향 일치를 비교합니다. AI 추천은 지역별 최대 20개 후보와 조건을 OpenAI에 보내 2~3개 관광지를 선택합니다. 앱이 중복·후보 외 ID·지역·여행일을 검사하고 직선거리 기준 순서를 계산합니다. 미리보기에서 직접 적용한 뒤 일정 만들기를 누릅니다. 식사·휴식은 시간표에서 추가·점검하세요. 추천 결과는 실제 영업·주차·도로 경로·예산 충족을 보장하지 않습니다.

Android 준비 화면의 ‘AI 연결 설정’에서 개인 키·모델을 저장/삭제할 수 있습니다. 웹은 BOPok_AI_KEY와 BOPok_AI_MODEL 서버 설정 및 기존 AI 요청 한도를 사용합니다. 기존 대체 관광지 AI와 같은 기기 키를 사용합니다. 외부 전송과 API 비용 동의 후에만 요청합니다.

검증: 단위 테스트 163개, 타입 검사를 포함한 웹 빌드, APK 빌드·서명 통과. 모바일 APK 웹 자산에서 기본 코스 추천과 모의 AI 코스 응답·직접 적용, 기존 택시/자가용 일정·저장/복원을 검증했습니다. 실제 API 호출과 실기기 검증은 하지 않았습니다.

화면 회귀 검사: 데스크톱/모바일 62개 중 최초 58개 통과. 새 상태 안내로 인한 선택자 중복과 과거 날짜로 고정된 테스트 데이터를 수정한 뒤, 관련 14개를 재실행해 모두 통과했습니다. 앱의 대중교통 미래 출발 검사 조건은 변경하지 않았습니다.

## 0.6.4 택시·자가용 선택

- 홈에서 택시 또는 자가용으로 시작하고 준비 화면에서 이동 수단을 바꿀 수 있습니다. 변경 시 이전 수단의 방문 순서·비용은 해제합니다.
- 추천 기준을 이동 거리 / 좌석·적은 보행 / 관심 경험·거리 균형으로 선택합니다. 등록 자료의 알려진 금지 조건을 걸러내고 근거와 함께 최대 5곳을 제시합니다. 거리 기준점은 선택한 출발 장소입니다. 미확인 접근성을 안전하다고 판단하지 않습니다.
- 자가용은 운전자 포함 인원과 정원, 연비·유류 단가·주차비·통행료를 받습니다. 비용은 직선거리 기반 입력 가정이며 실제 견적이 아닙니다. 모두 비우면 비용 미확인 상태로 순서만 계산합니다.
- 자가용 왕복 일정의 이동 구간도 자동차로 저장합니다. AI 대체 추천 요청에는 이동 수단과 추천 기준을 포함합니다. 주차·승하차 위치 등 확인되지 않은 자료는 생성하지 않습니다.
- JSON 호환성을 위해 기존 taxiPlan/taxiCapacity 필드명을 유지하며 새 transport 필드로 수단을 구분합니다. 이전 transport 없는 계획은 택시로 읽습니다.

검증: 단위 테스트 161개, 타입 검사, 웹 빌드, APK 서명 및 APK 웹 자산의 모바일 테스트(자가용 후보 추가·비용 미완성 거부·왕복·자동차 이동·저장/복원, 기존 택시 흐름) 통과. 실제 Android 기기와 실제 OpenAI 호출은 미검증입니다.

## 0.6.3 사용 흐름 개선

- 홈의 ‘택시 여행 빠르게 만들기’에서 조건 문답 없이 국내 실제 여행 준비로 이동합니다. 당일 여행·오늘 날짜를 기본값으로 사용하며 걷기 능력을 임의로 추정하지 않습니다.
- 여행 준비 단계를 표시하고 국내 자료 검색을 먼저 배치합니다. Android에서는 미연결된 해외 검색 입력을 숨기고 이용 범위를 안내합니다.
- 장소 종류별 필터, 선택한 장소만 보기, 선택 목록에서 해제, 장소별 보행·계단·좌석·원출처 확인을 추가했습니다.
- 요금·시간대·다도시 설정을 펼침 메뉴로 정리했습니다. 택시 결과는 방문 순서별 직선거리, 인원과 대수를 보여주며 실제 도로 거리·소요 시간으로 오해하지 않도록 표시합니다.
- AI 후보는 현재 장소와 이름·보행·계단·좌석을 표로 비교합니다. 교체 후 미확인 항목을 펼쳐 볼 수 있으며 API 키 미등록 시 요청 버튼과 안내로 상태를 알립니다.

검증: 타입 검사·웹 빌드·APK 서명 통과. APK 웹 자산의 모바일 화면에서 빠른 시작·오늘 날짜·장소 필터·선택 목록·거리 미리보기·저장/복원·JSON 내보내기·AI 교체 비교를 검사했습니다(AI 응답은 모의). 기존 실제 여행 E2E 4개와 택시 E2E 2개가 데스크톱/모바일 구성에서 통과했습니다. 테스트 선택자를 새 상세 정보/거리 표시 구조에 맞춰 수정한 뒤 해당 검사를 재실행했습니다. 실제 AI 호출과 Android 실기기는 아직 미검증입니다.

APK를 휴대폰으로 다운로드한 뒤 열어 설치합니다. Android가 요청하면 해당 다운로드 앱의 ‘알 수 없는 앱 설치’를 허용하세요. Play 스토어 출시본이 아닌 로컬 서명 미리보기입니다.

포함 기능: 전국 OSM 수집 자료 166,427건 검색과 후보 연결, 여행 일정 작성, 택시 방문 순서·복귀·사용자 요금 가정, 로컬 보관, JSON 파일 가져오기·내보내기, Android 인쇄/PDF 저장. 수집 자료의 출처·라이선스와 미확인 시설 안내를 유지합니다. 앱 삭제 시 로컬 일정도 삭제되므로 JSON으로 먼저 보관하세요.

공개 서버는 연결되지 않았습니다. 로그인·서버 공유·실시간 국내/해외 도시 검색·경로 조회·기존 AI 검토 설명은 사용할 수 없습니다. **새 ‘AI 대체 관광지 추천’은 본인의 OpenAI API 키를 등록하면 휴대폰에서 OpenAI로 직접 요청하는 별도 기능**입니다. 내장 자료는 실시간으로 갱신되지 않습니다. 외부 출처 링크는 휴대폰 브라우저에서 엽니다.

## 개인 AI 사용

1. 일정을 만든 뒤 ‘AI 대체 관광지 추천’을 엽니다.
2. 본인의 OpenAI API 키와 접근 가능한 모델을 입력하고 저장합니다. 기본 모델 입력값은 `gpt-4.1-mini`입니다. ChatGPT 구독과 OpenAI API 사용료는 별도입니다.
3. 교체할 관광 일정을 선택하고 여행 조건·후보의 외부 전송 및 API 비용에 동의한 뒤 추천을 요청합니다.
4. 추천 후보의 미확인 정보를 확인하고 ‘이 관광지로 교체’를 누릅니다. 인접 이동 구간도 변경되므로 경로 확인이 필요합니다. 저장된 택시 순서·요금 결과는 해제합니다.

키는 Android Keystore의 AES-GCM 키로 암호화해 앱 전용 저장소에 보관합니다. APK·브라우저 저장소·JSON 백업에 API 키를 넣지 않습니다. 키 삭제 버튼으로 암호문을 제거할 수 있습니다. OpenAI의 HTTPS Responses API로만 요청하며 리디렉션을 허용하지 않습니다. `store:false`, 최대 출력 800토큰, 기기당 하루 20회 요청 제한을 사용합니다. 이 기기 제한은 계정 전체의 과금 상한이 아니므로 OpenAI 계정에서도 사용 한도를 설정하세요. 키 등록 여부와 실제 연결 성공 여부를 구분합니다.

후보는 현재 여행에 불러온 같은 지역 관광지 중 조건 검사를 통과한 최대 20곳이며 AI는 그중 최대 3곳을 선택합니다. 고정 관광·연결 이동·휴식을 보존하고 알려진 조건 위반이 생기는 대안은 거부합니다. 미확인 시설·운영·접근성을 충족으로 판정하지 않습니다. AI 추천이 없거나 실패하면 기존 일정을 유지합니다.

## 다시 빌드

Node 24, Java JDK, Android SDK `platforms;android-35`, `build-tools;35.0.0`, zip이 필요합니다.

```sh
npm ci
ANDROID_SDK_ROOT=/path/to/android-sdk npm run build:android
node scripts/test-mobile.mjs
```

JRE만 있는 환경은 Eclipse ECJ 3.40.0 컴파일러 JAR 경로를 `ANDROID_ECJ_JAR`로 지정할 수 있습니다. SDK/ECJ 도구는 저장소에 포함하지 않습니다. 결과는 `android/build/bopok-android.apk`입니다. `.android-signing/preview.jks`는 로컬 미리보기 서명키이며 Git에 올리지 않습니다. 같은 설치본을 업데이트하려면 해당 키를 보관하고 `versionCode`를 증가시켜야 합니다. 키가 바뀌면 기존 앱을 삭제해야 하므로 JSON 백업 후 진행하세요. 정식 배포에는 관리되는 릴리스 서명과 별도 배포 검토가 필요합니다.

## 검증 범위

APK v2/v3 서명과 manifest/API 범위 검사, 모바일 크기의 Chromium에서 **실제 APK 웹 자산과 내장 관광 자료**로 검색·택시 일정 생성·로컬 저장/복원·JSON 내보내기를 확인했습니다. 외부 관광 API 모의 응답을 사용하지 않았습니다. 타입 검사와 서버·관광 자료·택시 단위 검사 24개 통과. 실제 Android 기기 설치, 네이티브 파일 선택·인쇄 UI는 이 환경에서 검증하지 못했습니다.

0.6.2 추가 검증: 타입 검사·웹 프로덕션 빌드, 대체 추천/기존 AI 설명/도메인 테스트 57개 통과. 모바일 화면의 추천·교체·저장 흐름은 **모의 Android bridge와 모의 AI 응답**으로 검증했습니다. 이 환경에는 AI 자격 증명이 없어 실제 OpenAI 호출 성공을 확인하지 못했습니다. Android Keystore 저장·네이티브 HTTPS 호출도 실기기 미검증입니다. 개인 키 등록과 유효한 API 결제가 있어야 실제 추천을 요청할 수 있습니다.
